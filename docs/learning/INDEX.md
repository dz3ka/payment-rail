# Payment Rail — Go Learning Journal

Payment Rail is a deliberate Go learning vehicle. Each milestone produces a lesson
capturing the **why** behind the code: the Go idioms used, the alternatives
weighed, and the mistakes avoided. This index links them in order.

| Milestone | Lesson | Focus |
|-----------|--------|-------|
| M0 | [m0-repo-skeleton.md](m0-repo-skeleton.md) | Module & `cmd/`/`internal/` layout, thin entrypoints, table-driven tests, graceful shutdown skeleton |
| M1 | [m1-double-entry-ledger.md](m1-double-entry-ledger.md) | Derived (never-stored) balances, `%w`/`errors.Is`/`errors.As` sentinels, and a fakeable `Store`/`Querier` transactor seam tested with no database |
| M1 | [m1-payments-idempotency.md](m1-payments-idempotency.md) | Composing a payment + journal entry in one tx via a shared `Querier` (`PostWithin`), an idempotency middleware built on a buffering `http.ResponseWriter`, and stable keyset (cursor) pagination |
| M2 | [m2-isolated-grpc-signer.md](m2-isolated-grpc-signer.md) | A pb-agnostic signing domain behind a proto↔domain gRPC adapter (sentinel→status mapping), a per-key `sync.Mutex` spend limiter with `{check→sign→commit}` as one critical section, defensive `deepCopy` of mutable `*big.Int`/slices at a key-holding trust boundary, and go-ethereum EIP-1559 signing |
| M2 | [m2-evm-chain-adapter.md](m2-evm-chain-adapter.md) | A concurrency-safe, chain-authoritative nonce allocator holding one `sync.Mutex` across the whole `{query→sign→broadcast→advance}` section (high-water committed only on success → gap-free), a ports-and-adapters seam reaching across a process boundary (adapter owns its `evm.Signer`/`ethRPC` interfaces + DTOs; proto↔domain mapping lives alone in the composition root), `*big.Int` mutable-pointer discipline, and an overflow-safe gas buffer via `math/bits.Mul64` |
| M3 | [m3-reorg-safe-settlement.md](m3-reorg-safe-settlement.md) | A poll-based confirmation/reorg watcher whose non-terminal `PhaseConfirmed` re-verifies the block anchor each pass (finality-depth eviction bounding the tracked map), reorg-safe ledger effects as block-hash-keyed mirror entries committed atomically via `ExecTx`, row-status-guarded idempotency (not the unique constraint, since a redelivered confirm trips the balance check first), `Resume`-vs-`Track` restart recovery, a zero-RPC poll-riding retry, and a `sync.Mutex` snapshotted rather than held across I/O (the inverse of M2's nonce lock) — plus a functional-core `poll()`/imperative-shell `Run()` split, consumer-defined `chainReader`/`StatusSink` seams that let a real simulated EVM stand in for a node, a durable `finalized` status bounding the seed query as well as the tracked map, and a lock-free concurrent re-scan |
| M4 | [m4-outbox-webhook-backbone.md](m4-outbox-webhook-backbone.md) | The transactional-outbox pattern (event + state in one `db.Querier` commit), an at-least-once relay draining with `FOR UPDATE SKIP LOCKED`, a poison-vs-transient Kafka consumer made idempotent by `UNIQUE(event_id, subscription_id)` + `ON CONFLICT DO NOTHING`, HMAC-SHA256 webhook signing over verbatim `json.RawMessage` bytes, clamped exponential backoff with dead-lettering + operator replay, and lease-based crash recovery — all transport behind consumer-owned ports, with sqlc's `DBTX` seam making same-tx emission free, embed-a-nil-interface strict fakes, and the trust-and-latency argument for holding a lock across a broker call but never across an untrusted HTTP one |
| M5 | [m5-policy-audit-controls.md](m5-policy-audit-controls.md) | A fail-closed policy pipeline ordered screen→velocity→four-eyes, a per-key velocity limiter charging inside a `pg_advisory_xact_lock` transaction (record-on-attempt), a four-eyes park→claim→broadcast state machine via `SELECT … FOR UPDATE` + guarded-`UPDATE` CAS, and an append-only hash-chained audit log (`sha256(prev ‖ canonical)`, length-prefixed preimage, app-assigned gap-free seq) that `audit verify` re-derives from genesis — and a running case study in which seams earn a port (`Screener`, `VelocityStore`) and which do not (`ApprovalStore`, `audit.Append`) |
| M6 | [m6-reconciliation-proof-of-reserves.md](m6-reconciliation-proof-of-reserves.md) | A tri-state `int` exit code (0 clean / 1 discrepancy / 2 operational) `os.Exit`-threaded through `main` so defers still run, reconciliation vs. proof-of-reserves as two orthogonal checks AND-ed into `Clean` (confirmed-pending funds as a bridge term, not a discrepancy), a keyset walk over a large settlements table terminating on a short page, and mixed `int64`-ledger / `*big.Int`-chain money arithmetic with fresh-allocation discipline, plus a row-value cursor comparison whose `(created_at, id)` tiebreaker is load-bearing and a stdlib-only `BalanceReader` port that fail-closes on untrusted `balanceOf` bytes |
| M7 | [m7-chaos-and-load-testing.md](m7-chaos-and-load-testing.md) | In-process fault injection at the `ledger.Store`/`ethRPC` seams (crash, connection kill via `pg_terminate_backend`, broken RPC, reorg) gated on an `assertConverged` closed-ledger + reconcile oracle, plus a stdlib-only load harness with per-worker lock-free latency slices, an `Op func(ctx) Outcome` seam, the cancelled-tail sample the deadline would otherwise poison, a traffic pattern derived from the SUT's idempotency and row-locking, and an honestly-scoped commit-throughput benchmark read through Little's Law |
| Ops | [ops-preview-environment-caller.md](ops-preview-environment-caller.md) | The caller half of a cross-repo contract: a `pull_request` workflow invoking bosun's reusable `workflow_call` (named secret instead of `secrets: inherit`, `pull_request` over `pull_request_target`, per-PR concurrency made safe by the callee's `if: always()` cleanup, `@main` inside a trust boundary), a topology-only `PaymentStack` template cut from four apps to one after a review falsified the plan's premise against the CRD, defaults derived by reading the producer's source (`expiresAt` from `CreationTimestamp` + SHA-free naming ⇒ TTL never extends), declarative minimalism as server-side-apply field ownership, and a label-length budget exhausted one derivation level deeper than its author counted |

_The journal is complete through M7 — every shipped milestone has a lesson._
